**Description**
```
Tally keeps track of what your team promised customers. It finds promises in Jira and Confluence, gets each one owned, ties it to the Jira work that delivers it, flags the ones slipping with plain rule-based reasons, and drafts the customer update for a person to approve.

Built on Atlassian Forge for Codegeist 2026. Runs on Atlassian: no data leaves your site.

What you'll see:
0:00 The problem: promises to customers get lost
0:13 Dashboard: open, at risk, overdue, no owner
0:34 Discovery inbox: possible promises found in Jira and Confluence
0:42 A person confirms each one. Nothing is tracked automatically
0:52 Evidence: the customer's own words, linked to the source
1:00 Linking the Jira work that delivers the promise
1:04 Teamwork Graph: parent epic and blocking work
1:14 Rule-based risk flags, each with its reason
1:35 Tally Agent in Rovo chat: answers from stored facts
1:52 Pasting a promise: the agent proposes, a person confirms
2:08 The same seven tools on Atlassian's MCP server
2:18 Customer update from stored facts, approved by a person
2:40 Settings: Jira, Confluence and Teamwork Graph checked as you

Features
- Discovery inbox with human confirm / edit / reject and duplicate warnings
- Commitments with owner, due date, evidence and linked Jira issues
- Nine rule-based risk flags (overdue, due soon, no owner, blocked and more)
- Customer updates drafted from stored facts only; copy only after approval; Tally never sends
- Tally Agent (Rovo), seven MCP tools, Teamwork Graph context

Code: https://github.com/ifeoluwaadegbulugbe/Tally
Docs, privacy policy and support: https://ifeoluwaadegbulugbe.github.io/tally-commitments-docs/

Narration is a computer voice. Demo data uses fictional companies.
```
